### 3.2 要件ステータス

| ステータス | 意味 |
|---|---|
| 提案 | 起票済み・未合意 |
| 合意 | 関係者で合意済み |
| 承認 | 本書の承認とともに確定 |
| 変更中 | 変更要求が進行中 |
| 削除 | 要件として取り下げ（履歴保持） |

### 3.3 優先度

| 区分 | 意味 |
|---|---|
| 必須 | 満たさなければ稼働できない |
| 高 | 稼働時に必要だが代替手段あり |
| 中 | 稼働後の対応でも可 |
| 低 | 余裕があれば対応 |

## 11. 変更管理

### 11.1 変更管理手順
1. 変更要求を起票（変更要求管理表に記入）
2. 影響範囲を分析（他要件、設計、工数、スケジュール）
3. 変更管理者・関係者がレビューし、採否を決定
4. 承認された場合、本書を改訂し、改版履歴（0.3）に記録
5. 関係者へ新バージョンを配布

### 11.2 変更要求管理表
